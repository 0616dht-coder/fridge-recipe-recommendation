냉장고 기반 맞춤 레시피 추천 서비스
보유 식재료와 소비기한을 관리하고, 재료 일치도·TF-IDF 유사도·소비기한을 함께 반영하여 활용하기 좋은 레시피를 추천하는 Streamlit 웹 애플리케이션입니다.

1. 프로젝트 개요

문제 상황
가정에서는 냉장고에 어떤 식재료가 있는지 정확히 파악하기 어렵고, 소비기한이 임박한 재료를 제때 사용하지 못해 식재료를 버리는 경우가 발생합니다. 
기존의 일반적인 레시피 검색은 사용자가 보유한 재료와 소비기한을 동시에 고려하지 못한다는 한계가 있습니다.

해결 목표
- 냉장고 재료와 소비기한을 한 화면에서 관리
- 보유 재료를 많이 활용할 수 있는 레시피 추천
- 소비기한이 임박한 재료가 포함된 레시피에 추가 가중치 적용
- 음식 종류, 조리 방법, 영양 조건, 제외 재료를 반영한 조건부 추천
- 좋아요·관심 없음 반응을 이용한 추천 순위 재조정


2. 주요 기능

냉장고 재료 관리
- 재료명, 수량, 단위, 기한, 기한 종류, 보관 방법 입력
- 주재료와 양념·조미료 구분
- 등록된 재료 수정 및 삭제
- 남은 일수에 따른 임박, 곧 임박, 여유 상태 표시

하이브리드 레시피 추천
- 보유 재료와 레시피 재료의 일치 및 부족 개수를 이용한 규칙 기반 점수
- 정규화된 재료 목록에 TF-IDF를 적용한 코사인 유사도 점수
- 규칙 기반 점수 70%와 TF-IDF 점수 30%를 결합한 하이브리드 점수
- 소비기한 임박 재료 활용 점수를 최종 점수에 15% 반영

추천 조건
- 음식 종류 선택
- 조리 방법 선택
- 제외할 재료 입력
- 최대 열량 설정
- 최대 나트륨 설정
- 최소 단백질 설정

사용자 반응 반영
- 추천 결과에 좋아요 및 관심 없음 기록
- 첫 번째 좋아요는 약 +5점, 관심 없음은 약 -5점 반영
- 같은 반응이 반복되면 최대 ±10점 범위 안에서 점진적으로 반영
- 사용자 반응은 추천 버튼을 다시 눌렀을 때 순위에 적용

외부 검색 연결
- 추천 레시피명을 이용한 유튜브 검색
- 추천 레시피명을 이용한 네이버 검색


3. 데이터
- 식품의약품안전처 레시피 데이터 cook.csv 사용
- 원본 레시피 1,156건 중 정제 후 1,152건 사용
- 주요 정보: 레시피명, 재료, 음식 종류, 조리 방법, 열량, 탄수화물, 단백질, 지방, 나트륨, 음식 이미지
- 재료명 표기 차이를 줄이기 위해 재료 정규화 사전 적용
- 영양정보 이상치 탐지 및 정제 변수 생성

배포 앱은 전처리가 완료된 데이터와 TF-IDF 행렬을 recommendation_data.pkl.gz에서 불러옵니다. 실행 과정에서 원본 cook.csv를 다시 전처리하지 않습니다.


4. 추천 처리 과정
  1. 사용자가 냉장고 재료와 소비기한을 입력합니다.
  2. 입력한 재료명을 정규화합니다.
  3. 레시피별 보유 재료와 부족 재료를 계산합니다.
  4. 냉장고 재료와 레시피 재료 사이의 TF-IDF 코사인 유사도를 계산합니다.
  5. 규칙 기반 점수와 TF-IDF 점수를 결합합니다.
  6. 소비기한이 임박한 재료가 포함된 경우 추가 점수를 반영합니다.
  7. 선택한 음식 종류·조리 방법·영양 조건·제외 재료를 적용합니다.
  8. 사용자 반응 기록이 있으면 개인화 조정 점수를 반영하여 상위 5개 레시피를 출력합니다.


5. 프로젝트 구조

fridge-recipe-recommendation/
  ├── app.py                         # Streamlit 화면 및 추천 로직
  ├── recommendation_data.pkl.gz    # 정제 레시피, TF-IDF 행렬 및 정규화 정보
  ├── requirements.txt              # 실행 라이브러리 버전
  ├── fridge_inventory.pkl          # 냉장고 초기 데이터
  ├── feedback_log.pkl              # 사용자 반응 초기 데이터
  └── README.md                      # 프로젝트 및 실행 가이드
  recommendation_engine.pkl은 이전 배포 방식에서 사용했던 구형 파일이며, 현재 안정화 버전에서는 사용하지 않습니다.


6. 실행 환경
  - Python 3.12
  - Streamlit 1.64.0
  - pandas 2.2.3
  - NumPy 2.1.3
  - PyArrow 24.0.0
별도의 API 키는 필요하지 않습니다.


7. 설치 및 실행 방법

1) 저장소 내려받기
git clone https://github.com/0616dht-coder/fridge-recipe-recommendation.git
cd fridge-recipe-recommendation
Git을 사용하지 않는 경우 GitHub에서 Code → Download ZIP을 선택한 뒤 압축을 풀어도 됩니다.

2) 가상환경 생성 및 실행
Windows 기준:
python -m venv .venv
.venv\Scripts\activate
macOS 또는 Linux 기준:
python3 -m venv .venv
source .venv/bin/activate

3) 라이브러리 설치
pip install -r requirements.txt

4) Streamlit 앱 실행
streamlit run app.py
실행 후 터미널에 표시되는 로컬 주소에 접속합니다. 일반적으로 http://localhost:8501에서 확인할 수 있습니다.


8. Streamlit Community Cloud 배포
  1. 프로젝트 파일을 GitHub 저장소의 최상위 폴더에 업로드합니다.
  2. Streamlit Community Cloud에서 새 앱을 생성합니다.
  3. 저장소와 main 브랜치를 선택합니다.
  4. Main file path를 app.py로 설정합니다.
  5. Python 버전은 3.12를 선택한 뒤 배포합니다.
배포 앱: https://fridge-recipe-recommendation-j83qqicpewr4aj5ahj4bvr.streamlit.app/


9. 실행 시 참고사항
- fridge_inventory.pkl 또는 feedback_log.pkl이 비어 있거나 손상된 경우 앱이 빈 데이터로 자동 복구합니다.
- 냉장고 및 사용자 반응 데이터는 Streamlit 서버의 로컬 파일에 저장되므로 서버가 재시작되면 초기 상태로 돌아갈 수 있습니다.
- 추천 데이터는 함수 객체가 포함된 cloudpickle 대신 데이터 전용 압축 파일로 저장하여 배포 환경 간 호환성을 높였습니다.


10. 한계
- 현재 사용자 반응 기능은 동일 레시피의 점수를 재조정하는 방식이며, 사용자의 음식 종류나 재료 선호를 학습하는 모델은 아닙니다.
- 계정 기능이 없어 사용자별 냉장고와 선호도를 분리하여 장기간 저장할 수 없습니다.
- 냉장고 재료를 사용자가 직접 입력해야 합니다.
- 배포 서버의 로컬 저장 방식은 장기적인 데이터 보관에 적합하지 않습니다.


11. 향후 개선 계획
- 누적된 사용자 반응을 이용한 개인별 추천 가중치 학습

- 영수증 이미지 인식 또는 바코드 인식을 통한 재료 입력 자동화
- 소비기한 임박 알림 및 장보기 목록 기능
